# Роли пользователей в FamilyPay

## Структура приложения

### 1. **Landing Page** (`/`)
- Доступна всем
- Маркетинговая страница с информацией о продукте

### 2. **Страница входа** (`/login`)
- Доступна всем
- Вход/регистрация через email или Google

### 3. **Dashboard** (`/dashboard`) - ✨ Личный кабинет
- Доступен всем **авторизованным пользователям**
- Управление своими финансами:
  - Просмотр баланса
  - Добавление доходов/расходов
  - Создание целей и бюджетов
  - Управление семьями
  - Отчеты и аналитика

### 4. **Admin Panel** (`/admin`) - 🔐 Админ-панель
- Доступна только **администраторам** (роль `ADMIN`)
- Управление всей системой:
  - Все пользователи
  - Все семьи
  - Все транзакции
  - Система категорий
  - Статистика системы

---

## Роли пользователей

### USER (обычный пользователь)
- После входа → `/dashboard`
- Может управлять своими финансами
- Может создавать семьи и приглашать членов
- **Не имеет доступа** к `/admin`

### ADMIN (администратор)
- После входа → `/dashboard` (может сам перейти в `/admin`)
- Имеет все права `USER`
- **Полный доступ** к админ-панели `/admin`
- Может видеть и управлять всеми данными в системе

---

## Управление пользователями

### Создать тестового пользователя
```bash
npx tsx create-test-user.ts
```

Создаст пользователя:
- Email: `test@example.com`
- Password: `password123`
- Роль: `USER`

### Назначить администратора
```bash
# Отредактируйте email в файле make-admin.ts
npx tsx make-admin.ts
```

### Добавить пароль к Google аккаунту
```bash
# Отредактируйте email и пароль в файле add-password-to-user.ts
npx tsx add-password-to-user.ts
```

### Проверить пользователя
```bash
# Отредактируйте email в файле check-user.ts
npx tsx check-user.ts
```

## Логика перенаправления

### При входе:
1. **Пользователь входит** через `/login`
2. **Проверка учетных данных**
3. **Перенаправление**:
   - Все пользователи → `/dashboard`

### При попытке доступа к `/admin`:
1. **Проверка авторизации** (есть ли токен?)
   - ❌ Нет → перенаправление на `/login`
2. **Проверка роли** (ADMIN?)
   - ❌ Нет → перенаправление на `/dashboard`
   - ✅ Да → доступ разрешен

### При попытке доступа к `/dashboard`:
1. **Проверка авторизации** (есть ли токен?)
   - ❌ Нет → перенаправление на `/login`
   - ✅ Да → доступ разрешен

## Примеры использования

### Обычный пользователь (USER)
1. Регистрируется через Google или email
2. Попадает на `/dashboard`
3. Создает семью, добавляет счета
4. Начинает вести учет финансов
5. ❌ Не может зайти в `/admin`

### Администратор (ADMIN)
1. Входит в систему
2. Попадает на `/dashboard`
3. Может работать как обычный пользователь
4. Может перейти в `/admin` для управления системой
5. ✅ Видит всех пользователей и все данные
