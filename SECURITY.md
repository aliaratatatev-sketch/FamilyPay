## Рекомендации по безопасности

### Защита секретов

1. **Никогда не коммитьте `.env` файл**
   - Убедитесь, что `.env` в `.gitignore`
   - Используйте `.env.example` как шаблон

2. **Используйте сильные секреты**
   ```bash
   # Генерация безопасного NEXTAUTH_SECRET
   openssl rand -base64 32
   ```

3. **Ротация ключей**
   - Регулярно меняйте API ключи (раз в 3-6 месяцев)
   - При компрометации немедленно сгенерируйте новые ключи

### База данных

1. **Используйте сильные пароли**
   - Минимум 16 символов
   - Включайте буквы, цифры, специальные символы
   - Не используйте словарные слова

2. **Ограничьте доступ**
   - Используйте whitelist IP адресов
   - Не открывайте базу данных для всего интернета

3. **Бэкапы**
   - Регулярно делайте резервные копии
   - Храните бэкапы в безопасном месте
   - Тестируйте восстановление из бэкапов

### Продакшен

1. **HTTPS обязателен**
   - Используйте Let's Encrypt для бесплатного SSL
   - Настройте автоматическое обновление сертификатов

2. **Переменные окружения**
   - Храните секреты в безопасном хранилище
   - Используйте сервисы: Vercel Secrets, AWS Secrets Manager, HashiCorp Vault

3. **Мониторинг**
   - Настройте логирование ошибок (Sentry, LogRocket)
   - Мониторьте необычную активность
   - Настройте алерты на критические события

### Зависимости

1. **Регулярные обновления**
   ```bash
   # Проверка уязвимостей
   npm audit
   
   # Автоматическое исправление
   npm audit fix
   
   # Обновление зависимостей
   npm update
   ```

2. **Проверяйте перед установкой**
   - Используйте только проверенные пакеты
   - Проверяйте количество загрузок и активность
   - Читайте отзывы и issues

### Аутентификация

1. **NextAuth.js настройки**
   - Используйте `secure: true` для cookies в продакшене
   - Настройте правильный `NEXTAUTH_URL`
   - Используйте session strategy: "jwt"

2. **Пароли пользователей**
   - Минимальная длина: 8 символов
   - Используется bcrypt для хеширования
   - Никогда не храните пароли в открытом виде

3. **2FA (опционально)**
   - Telegram Bot для дополнительной безопасности
   - Email подтверждение для критических операций

### API ключи

1. **Ограничение использования**
   - Groq API: бесплатный лимит - следите за использованием
   - Настройте rate limiting для API endpoints

2. **Разделение окружений**
   - Используйте разные ключи для dev/staging/prod
   - Не используйте продакшн ключи в разработке

### Код

1. **Валидация входных данных**
   - Всегда валидируйте user input
   - Используйте Zod или Yup для схем валидации
   - Санитизируйте данные перед сохранением

2. **SQL Injection защита**
   - Используйте Prisma ORM (защищает автоматически)
   - Никогда не используйте raw SQL с user input

3. **XSS защита**
   - React экранирует данные по умолчанию
   - Будьте осторожны с `dangerouslySetInnerHTML`
   - Используйте Content Security Policy

4. **CSRF защита**
   - NextAuth.js включает CSRF защиту
   - Используйте SameSite cookies

## Чек-лист перед деплоем

- [ ] HTTPS настроен и работает
- [ ] База данных защищена и доступна только с whitelist IP
- [ ] Настроен мониторинг и логирование
- [ ] `npm audit` не показывает критических уязвимостей
- [ ] Настроены бэкапы базы данных
- [ ] Rate limiting настроен для API
- [ ] CSP headers настроены
